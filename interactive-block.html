Does Bitcoin's fee market price permanence, or just congestion?

BIP-141 gave witness data a 4× weight discount. It was designed to fix malleability — not to create a pricing structure for permanent data storage. The result: an unpriced externality that grows with every inscription.

The fee market prices inclusion in the next block (~10 min). It does not price lifetime storage in every full node's UTXO set (indefinite). These are different market failures.

Exploratory Directions

After two failed proposals (v1: Priority Oracle, v2: Externality Fee), the community feedback pointed to relay policy as the only viable lever. Relay nodes both bear storage costs and set relay policy — they're the natural pricing point.

UTXO-Aware Relay Fee Recommended

Extend minrelaytxfee so relay nodes apply a fee multiplier for transactions above a state footprint threshold. Each node sets their own multiplier.

✅ Each node prices itself — market mechanism
✅ No consensus change — purely relay policy
✅ Miners unaffected
⚠ Risk: low adoption by relay operators

BIP for State-Conscious Relay Exploring

A BIP standardizing state impact metrics and recommending fee schedules. Wallet-side fee estimation guidance for users.

✅ Ecosystem alignment without mandating adoption
✅ Formalizes existing ordinal-filtering practice
✅ BIP process ensures thorough incentive analysis
⚠ High scrutiny — but that's the point

Multi-Tier Relay Market Speculative

Relay nodes advertise tiered fee schedules during peer handshake. Wallets discover the cheapest path for their transaction type.

✅ Most market-driven approach
⚠ Requires P2P protocol changes
⚠ Higher complexity — explore only if A/B insufficient
The Journey
v1 — Failed
Priority Oracle
Classify tx as financial/data, allocate 30% block floor. Miners won't leave fees on the table. Classification with no economic consequence is a signaling game with zero equilibrium.
v2 — Failed
Externality Fee
Price the "true storage cost" via formula. Any formula-based fee is an arbitrary tax. No mechanism to discover the "true cost" of a transaction to the network.
v3 — Open Research
Relay Policy Research + Cost Model
Built a complete UTXO cost model with live verification. Surveyed state expiry, covenant proposals, and relay policy. Three directions being explored above. The question is still open.
Related Proposal: BIP-110
BIP-110 is a temporary 1-year soft fork that bans most inscription methods at the consensus level: limits witness data pushes to 256 bytes, bans OP_IF/OP_NOTIF in Tapscripts (the inscription vector), limits scriptPubKeys to 34 bytes, and bans Taproot annexes. It uses a controversial 55% miner threshold instead of Bitcoin's usual 95%.

Same diagnosis

Both BIP-110 and this research agree that data inscriptions create costs for node operators that the fee market doesn't price. The 4× SegWit witness discount (BIP-141) was never designed as a state-pricing mechanism.
✅ Same problem identification

Different prescription

BIP-110 uses a consensus-level ban (temporary soft fork, 55% threshold). This research explores relay-level pricing (each node sets its own fee multiplier, no consensus change). Our cost model provides the economic data BIP-110's rationale lacks.
⚠ Different approaches to same problem
How our research fills BIP-110's gap: BIP-110's rationale is ideological ("Bitcoin is money, not data storage") — it has no economic model showing why data storage is harmful. Our cost model provides the missing data: $0.008/inscription lifetime storage cost, $9.2K/yr aggregate externality, sensitivity analysis across adoption scenarios. These numbers give both supporters and critics of BIP-110 a shared factual basis for the debate.
Reference: CashTokens (Bitcoin Cash)
Bitcoin Cash's native token protocol (CHIP-2022-02) offers an interesting contrast. Tokens are consensus-enforced with 40-byte NFT commitments — no envelope hacks. BCH has no SegWit, meaning no 4× witness discount subsidizing data. Result: inscription activity on BCH (0.5% of 32 MB blocks) causes zero congestion. This validates our SegWit discount analysis but doesn't help Bitcoin — CashTokens required a hard fork.
